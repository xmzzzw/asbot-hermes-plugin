# AS-BOT Hermes 插件

给已有官方 Hermes Agent 增加 AS-BOT 截图与经济日历工具。公开仓库为 [xmzzzw/asbot-hermes-plugin](https://github.com/xmzzzw/asbot-hermes-plugin)，插件版本以当前安装包的 `release.json` 为准。这不是 Hermes 的分支、替代客户端或指定版本的 Hermes；安装器不会安装、升级、降级 Hermes，不改变模型、搜索、审批、微信登录或其他插件。`bin/plugin.py` 只是本插件的安装与认证助手；旧入口 `bin/client.py` 保留兼容。

固定发行版、完整源 SHA 和校验值都指 **AS-BOT 插件**，用于核对来源与恢复，与你的 Hermes 版本无关。基础接入按官方公开插件接口检测能力，不再比较微信适配器的源码指纹。未来 Hermes 若破坏公开接口仍可能需要插件适配；不能承诺任何未来版本永不受影响。

先由可信渠道取得发行包及**独立提供的 zip SHA-256**，核对整个 zip 后解压。包内 `release.json` 记录完整来源 SHA、插件版本（协议字段仍叫 `clientVersion`）和文件校验值；自带校验清单不能单独证明来源。不要复制私有 AS-BOT 仓库、Owner 工具或私密配置。

## 让管理员协助安装

如果管理员给你的是设备接入流程，从公开发行页选择与你系统相符的正式安装器。macOS 打开已签名和公证的 DMG 并双击里面的 AS-BOT Hermes。Windows 打开有有效 Authenticode 签名的 EXE，已有 Hermes 在 WSL 时选择对应发行版。Linux 或 WSL 也可以解压已核对的插件包，运行 `sh AS-BOT.sh`。带 `.simulation` 的文件仅用于隔离演练。

在自己设备上确认安装，选择已有 Hermes 配置和已批准的微信私聊。是否允许长期更新、诊断、修复，以及是否允许空闲时重启现有 Gateway，分别由你选择。把窗口里的**设备卡**发给管理员。四个字段是文件格式、申请编号、设备公钥指纹和配置名，副本在本机状态目录的 `device-card.json`。配对码、微信内部 ID 和密钥都留在本机。

首装通过本机主动 HTTPS 联系，可关闭窗口。在 macOS 登录会话、Windows 当前用户任务或 Linux 的 systemd 用户会话可用时，每分钟检查一次。WSL 优先使用发行版里的 systemd 用户定时器。没有该定时器时可由已登录的 Windows 用户任务唤起同一 WSL 发行版和同一普通用户。只同意首装时，接入完成或首次等待满 24 小时后停止。启用长期维护后，设备下次上线会检查这个插件的固定任务。没有可用的用户定时器时，安装器会提示处理；管理员也可以通过你已有的 SSH 接入运行同一款插件助手。Gateway 繁忙、身份不符或承载其他配置时保留当前进程。

管理员要求会员本人核验时，在设备上的安装器选择“在本机验证我的 Discord”，用自己的 Discord 登录。浏览器不能打开时，安装器提供仅存在本机私密文件里的 Discord 指令。请勿转发该文件或把里面的配对码一起发给管理员。

再次打开安装器，可以查看同一张卡或撤回协助授权。撤回立即阻止本机后续任务。离线撤回时，恢复联网后再打开一次可核对服务器回执。已经安装的插件保留原账号和日常功能；设备账号停用由管理员处理。显示已安装、等待 Gateway 绑定或等待回执时，请保留原申请。微信收图仍需在自己的私聊确认。

## 原有邀请码与网页接入

让你的 Agent 阅读 [AGENTS-client.md](AGENTS-client.md) 和 [安装与问题处理指南](AGENT-INSTALL.md)，使用你**已有的 Hermes Python 环境**运行：

```sh
python3 bin/plugin.py setup
python3 bin/plugin.py activate --wait 60
python3 bin/plugin.py status
python3 bin/plugin.py doctor
```

安装助手自动检测 `HERMES_HOME`，未设置时使用 `~/.hermes`。上述接入码流程只有一个时自动选择，多个时在本机选一个。路径含中文、空格时加引号。

Web 自助开放后，会员和交易员用 `python3 bin/plugin.py setup --manage`，在[接入页](https://asbot-connect.zhouzhou.edu.kg/connect/manage)登录自己的 Discord，填写有效 24 小时的 `pairingCode`。确认后旧码不能再用；未开通时可在原安装目录运行 `status` 换发过期的配对码。网页只显示已配置微信、存在已批准私聊且可新装插件的选项；只有一个时默认勾选，多个可同时勾选。确认后运行 `activate --wait 120`，它会先核对选中的本机绑定。多个配置归在同一台设备下，共享额度，撤销该设备会一起停用。原始微信 ID、登录凭据和本机路径只留在设备上。

接入码只在隐藏终端提示中输入，不放在命令参数、环境变量或日志。直接回车也可先申请、等待管理员审核。会员按管理员要求在 Discord 使用 `/接入确认 配对码`，或运行 `activate --auth web` 登录 Discord。本人身份验证成功仍需管理员批准和资格检查。

状态依次区分安装、待审核、待认证、开通中、API 接入已确认和待真人收图。`ACTIVE`、接口检查及热加载成功不等于微信收图验收。无法热加载会显示 `PLUGIN_RELOAD_PENDING`，不会启动或重启 Gateway；需要重启时由设备主人安排空闲窗口。发生结果未知的写入，只保留原申请继续查询，不重新申请或重放。

## 官方接口模式与验收边界

新安装默认使用 `official` 模式。明确截图指令 `1`、`BTC1`、`截图1` 由插件在官方准入 hook 中接管；后台直接调用 AS-BOT，再通过现有微信连接的公开发图接口交付。**这些明确指令不进入模型，不消耗模型 Token。** 普通聊天、图片分析以及自然语言让 Agent 选择工具时，仍可能调用用户自己的模型。

平台连接回调需要绑定现有微信连接。首次安装或热加载后未绑定时，明确截图指令返回通道未就绪提示，不退回模型。由设备主人在空闲窗口确认后重启现有 Gateway 一次，安装器不会擅自重启、启动第二个微信消费者或重新登录微信。插件不修改 Hermes 源码或适配器字段，也不自行实现微信上传协议。

发送“截图帮助”会列出当前账号允许查看的模板编号与描述；原生回图也附上对应模板说明。帮助与明确截图指令都不调用模型。

截图范围由服务器授权决定：动态全部的账号会自动获得后续新增的截图指令，帮助列表也随当前目录变化。v1.5.1 支持多位数字编号；旧版固定 `0–9` 的插件需要走原安装自己的 `update`。未登记的编号会被拒绝，不占截图额度。配额、会员资格和设备撤销仍然生效。

同模板需要新图时，请分条发送 `1 #A01`、`2 #A02`、`1 #A03`。这仍是明确的零模型指令，编号只让文本不同；不要用新编号自动重试结果未知的任务。官方微信端可能在插件收到消息前过滤完全相同文本，所以原样重复数字 `1→2→1`、忙时独立旁路及任意旧图引用恢复仍须分别验证，不作基础保证。不会为这些能力放宽权限、修改上游去重或延长全局 hook 超时。

完成连接后，请实际发送明确指令并确认原生图片，核对未启动模型回合，再核对日历与旧图引用。`ACTIVE`、API 成功及热加载成功都不能代替真实收图；未有回执前保持 `qualified:false`。详见 [Agent 处理步骤](AGENT-INSTALL.md)。

## 升级、恢复与卸载

v1.7.1 修复旧截图任务已经在服务端结束、却仍占住新截图队列的问题。插件只读取原任务状态，确认结束后才放行下一条指令。旧截图不会重新提交，也不会补发；状态仍不明确时，继续按原任务核对。

取得新插件包、独立核对 zip 校验值后，使用原 Hermes Python 和同一状态目录运行：

```sh
python3 bin/plugin.py update
```

原安装使用过 `--state-dir` 时，更新也要带上同一个路径。更新后先在已有微信私聊实测一条截图指令；如果通道没有重连，由设备主人在空闲时重启现有 Gateway。无需重新申请或配对。

只升级本安装回执拥有的插件文件；保留原始备份、账号、额度、图片账本和恢复密钥。发现后续用户改动时停止，不覆盖。旧 `1.0.0` 安装需明确核对传输模式后迁移，不能静默切换功能。凭据轮换用同一状态目录再次运行 `activate`；结果未知时只查询当前凭据版本。

为保留恢复记录，历史状态目录不改名：macOS `~/Library/Application Support/asbot-client`，Linux `${XDG_STATE_HOME:-~/.local/state}/asbot-client`，Windows `%LOCALAPPDATA%\asbot-client`。可用 `--state-dir` 指定独立私密目录，必须在仓库和发行包之外；每个安装实例独立凭据，不要复制给另一设备。POSIX 私有权限或 Windows 当前用户 ACL 无法验证时拒绝继续。Windows 实机资格仍待验。

需要卸载时，用原状态目录运行 `python3 bin/plugin.py uninstall`。它只恢复本安装的原配置并移除本插件；服务端撤销由管理员操作。不要发送 `enrollment.json`、`bridge.json` 或私有备份，排查只需申请编号、阶段和错误码。

## 管理更新

在 macOS Apple Silicon 和已验证的 Hermes 0.22.2 上，从已独立核对 ZIP 哈希的发行包一次性启用：

1. 对 v1.4.x / v1.5.x，先用新包里的 update 和原状态目录安装受管版本，确认正确的微信配置已实际加载。若热加载未完成，由设备主人按前面的说明安排现有 Gateway 重启。
2. 从同一个新包运行 python3 bin/plugin.py enable-updates --state-dir <原状态目录>。仅在你同意空闲时重启现有 Gateway 及失败后的恢复重启时加 --restart-gateway。参加获准试用才加 --pilot-updates。
3. 使用 pause-updates / resume-updates 和原状态目录控制自动安装。已登录管理页的「立即更新」仍可以为自己的设备登记更新；未连接的设备下次联络时处理。

更新器只使用已批准的签名包，并保留原配对、微信登录和历史记录。显示「已恢复旧版」表示实际加载与微信连接都已重新核验；显示需检查 Gateway 时，可先运行 doctor 并查看现有 Gateway，勿创建新接入或重复截图。
